
# 口径正交化确认（Framing Caliber Orthogonalization）

> 用途：在 **G1 问题框架化** 阶段，把题目里**容易产生‘口径问题’的定义维度**拆成**相互正交**的三根轴，分别让建模者确认，避免不同人/不同子问题对同一概念用了不同口径。
> 总清单见 `references/reference-sources.md`；政策见 AGENTS.md「Problem-Start Mode Gate / Reference Consultation」。
> 本指南由 `problem-parser` / `problem-classifier`（G1）与 `decision-prompt-builder` 引用；**口径三项都是完全由人确认的判断**，AI 只列选项与后果，不代选。

**什么是‘口径正交化’**：题干里一个词（如‘指标’‘服务’‘覆盖’）往往隐含多个独立定义维度。把每个维度**单独设问、单独记录**（正交 = 互不依赖、可各自独立取值），就不会把‘判据粒度’‘谁服务谁’‘总分怎么算’混成一团，从而避免口径漂移。

## 三根正交轴（每根单独确认、单独记录）

### 轴 1 —— 判据粒度（Criterion Granularity）

问的是：**按什么粒度去套用评价/计数/达标判据**。只影响‘判据作用在哪个对象层级’，不影响‘总分怎么加总’（那是轴 3）。
选项（可尽量多给，供选择）：
- A. 逐子问题（per-subquestion）：每个 Q 用各自判据，互不合并。
- B. 逐对象/逐实体（per-object / per-entity）：对每个对象（城市、订单、商品、时段……）单独计一次。
- C. 逐类别/逐类型（per-category / per-type）：按对象类型分组后逐类评价。
- D. 逐时段/逐阶段（per-period / per-stage）：按时段/阶段/批次分别评价。
- E. 逐方案/逐策略（per-scheme / per-strategy）：对每个候选方案或策略分别评价。
- F. 整体/汇总（overall / aggregate）：只给一个总判据，不分层。
- G. 分层/两级（hierarchical / two-level）：先逐对象（子）评价，再汇总成整体（父）。
- H. 极值／最劣口径（extreme / worst-case）：只取最优或最差（如最大延误、最小利润、最坏情形）。
- I. 分布/概率口径（distribution / probabilistic）：以分布、期望、分位数、置信区间计。
- J. 阈值/达标口径（threshold / attainment）：以‘是否达到某阈值/满足约束’为成功。
- K. 波动/灵敏度口径（variation / sensitivity）：以稳健性、敏感性、方差衡量。
- L. 可加总 vs 不可加总（additive vs non-additive）：判据是否跨对象可加总（含是否允许跨对象抵消）。
- M. 综合评分口径（composite-score）：用加权评分/TOPSIS 等生成每个对象一个综合分。
- N. 占比/人均口径（ratio / per-capita）：以比例、人均、单位成本产出计，而非绝对数。
- O. 都不合适 / 补充约束。

判据粒度的常见后果：粒度选错了，会让‘逐项达标’与‘整体达标’得出不同结论（例如‘平均达标’掩盖‘个别不达标’）。

### 轴 2 —— 服务关系（Service Relationship）

问的是：**服务/指派/覆盖/供给的实体之间是什么关系**。只影响‘谁服务谁、能否不服务’，不影响‘每个粒度怎么套判据’（轴 1）与‘总分怎么加总’（轴 3）。
选项（可尽量多给）：
- A. 一对一（1:1）：一个服务者只服务一个对象（严格匹配）。
- B. 一对多（1:N）：一个服务者可服务多个对象（共享服务能力）。
- C. 多对一（N:1）：多个服务者共同服务一个对象（协同/叠加）。
- D. 多对多（N:M）：任意服务者-对象匹配。
- E. 全覆盖/无遗漏（full coverage）：每个对象都必须被服务到（补全最后一环）。
- F. 部分覆盖/可拒绝（partial coverage / rejectable）：允许不服务、放弃或拒绝（含惩罚）。
- G. 顺序/排队（sequential / queueing）：先到先服务、优先级调度、排队等待。
- H. 分层/级联（hierarchical / cascade）：层级服务链（如省-市-县、总仓-分仓、总站-梯级）。
- I. 共享/竞争（shared / competitive）：多服务者争抢同一资源，或资源被共享。
- J. 可替换/多源（substitutable / multi-source）：一个对象可由多个来源之一服务。
- K. 优先/加权（priority / weighted）：不同对象/服务者有不同的优先级或权重。
- L. 双向/互惠（bidirectional / mutual）：相互服务或双向关系。
- M. 离散 vs 连续强度（discrete vs continuous service intensity）：服务强度是离散档还是连续量。
- N. 时间窗/时段约束（time-windowed）：仅在特定时段、窗口或时限内可服务。
- O. 不适用（本问无服务/指派关系）。
- P. 都不合适 / 补充约束。

服务关系常见后果：把‘必须全覆盖’与‘可部分覆盖’混用，会让约束条件完全相反；把‘1:1 匹配’与‘1:N 共享’混用，会让容量/上限建模出错。

### 轴 3 —— 总指标（Overall / Total Indicator）

问的是：**把一个层级里的多个值合并成一个总/最终指标时，怎么加总**。只影响‘总分算法’，不影响‘套判据的粒度’（轴 1）与‘谁服务谁’（轴 2）。
选项（可尽量多给）：
- A. 求和（sum）：总量/总成本/总收益直接相加。
- B. 加权和（weighted sum）：按权重相加（权重需说明来源，如熵权/主观/等权）。
- C. 平均/均值（mean）：算术平均。
- D. 加权平均（weighted mean）：加权平均。
- E. 最大值（max）：取最大（如最长、最高、最坏收益）。
- F. 最小值/最劣（min / worst-case）：取最小（如最短、最低、最差表现）。
- G. 极差/波动（range / volatility）：看最大最小之差、方差、标准差。
- H. 排序/名次（rank）：只比较排名，不比较绝对量。
- I. 达标率/覆盖率（attainment / coverage rate）：满足某阈值/覆盖的比例。
- J. 效用/多目标（utility / multi-objective）：用效用函数或 Pareto 权衡多目标。
- K. 期望/风险指标（expectation / risk measure）：期望、方差、CVaR、分位数、风险调整。
- L. 比率/效率（ratio / efficiency）：得分率、人均、单位产出、投入产出比。
- M. 增长/变化率（growth / change rate）：相对变化而非绝对量。
- N. 罚函数/正则（penalty / regularized）：含违规或代价惩罚项的聚合。
- O. 归一化后汇总（normalized aggregate）：先标准化/归一化再加总。
- P. 综合评分（composite score）：TOPSIS/灰色/熵权等多指标综合。
- Q. 都不合适 / 补充约束。

总指标常见后果：求和 vs 取均值 vs 取最劣，会得出完全不同的‘好坏’结论；多目标若不明确加权，就无法给出唯一排序。

## 口径正交化确认的动作（G1）

1. 在第一遍解析后、方法筛选前，把上述三根轴**各出一题**（可用一张卡三问，或三张卡），每题给出尽量多的选项 + 每项后果，请建模者逐轴确认。
2. 三轴**互相正交、独立确认**：选了一个粒度不影响服务关系与总指标；禁止把三轴混成一题。
3. 每根轴都给出‘都不合适 / 补充约束’；用户可自定口径。
4. 把每根轴的答案经 `modeler-decision-logger` 原话记录到 `planning/framing_decisions.jsonl`（全局）或 `methods/Qx/qx_decisions.jsonl`（子问题级），`decision_type: framing_caliber`，每条一条记录（`criterion_granularity` / `service_relationship` / `overall_indicator`）。
5. 口径确认后，把它写入 `planning/parse/problem_parse.json` 的每条子问题 `success_criteria` / `ambiguities`（或 `caliber` 字段），确保下游（分类、方法筛选、结果分析、论文）**沿用同一口径**。

【记录字段建议】每条 DECIDED 记录：
- `decision_id`：如 `q1_caliber_criterion_granularity`（或全局 `g_caliber_*`）；
- `decision_type`：`framing_caliber`；
- `choice`：所选选项字母 + 简述（如 `B. 逐对象/逐实体`）；
- `rationale`：一句证据/理由；
- `evidence_refs`：可空或指向题目/数据来源；
- `source`：建模者原话（`user_answer`）。

## 其他可能出现的题目分析问题（额外排查清单）

除三根轴外，第一遍解析时要对下列问题逐项标记‘已确认 / 待确认 / 不适用’，并在 `problem_parse.json` 的 `ambiguities` 或 `risks` 里留痕：
- 1. **单位/量纲**：各变量的单位是否一致、是否需要换算；时间/金额/面积/温度等口径是否统一。
- 2. **时间口径**：是时点还是时段；起止、步长、时间单位（秒/分/时/天）；是否跨时段/跨天/跨年度。
- 3. **数据口径**：样本范围、缺失与异常、粒度、时间/空间对齐、是否有聚合/拆分歧义、重复项。
- 4. **对象范围/边界**：哪些对象计入、哪些不算；边界对象（刚好在门槛上）如何处理；是否含排除项。
- 5. **指标定义歧义**：题干一个词（如‘效率’‘风险’‘最优’）可多解时，需先锁定定义。
- 6. **多目标冲突**：多个目标是否冲突、优先级/权重是否已给、是否有可接受的折衷。
- 7. **硬约束 vs 软约束**：哪些必须满足、哪些可放宽（含违约代价）；约束是否可违反仍‘成功’。
- 8. **尺度/量级**：是否存在极端大数/小数、量纲悬殊；是否因此需要归一化或对数处理。
- 9. **因果 vs 相关**：题目要求‘关系’时，是只需相关性还是必须因果（避免把相关当因果）。
- 10. **比例 vs 绝对数**：比较时用比例、人均还是绝对量；分母口径是否稳定。
- 11. **评价基准**：与谁比（基线/官方值/历史值）；基线定义是否与主方法同口径。
- 12. **口径随子问题漂移**：各 Q 是否用同一口径；同一概念在不同 Q 是否给不同符号/定义。
- 13. **边界/退化情形**：空集、全同、零值、极端值、到达极限时模型/指标是否还有意义。
- 14. **采样/代表性**：样本是否代表总体；是否需加权/分层；外推是否成立。
- 15. **单位换算/标准**：是否存在多种标准（如不同国家/行业标准）需统一。
- 16. **输出格式与对比性**：输出是否可比较；是否需附置信度/不确定性。

## 约束

- 口径三项都是**人**的判断：AI 只列全选项 + 后果，不代选、不替建模者写理由。
- 只在**确有歧义且影响下游**时设问；纯机械可判定的（如单位换算结果）不要问人。
- 口径确认后不得在下游悄悄改口径；要改必须回到 G1 重新确认并记 `freeze_change_log` 同级留痕。
- 正式建模模式下，可对照 `resource-library/` 与 `references/award-papers/` 常见口径写法。
