## 亮点（结构层面，为什么值得学）
### 整体结构
- **问题重构分层 → 假设 → 符号表 → 逐题"建模→求解→结果→小结"→ 模型评价/改进 → 附录代码与文件清单**。
- **形成闭环**：Q1 抽样 → Q2/Q3 决策 → Q4 扰动回灌（贝叶斯/鲁棒），前后呼应。
- **每个子问的"模型-解-析"闭环**都给出清晰过渡（如"小规模枚举→爆炸切 DP"的判据直接写进问题分析）。

### 局部结构
- **符号表必须完整且正文真正使用**：定义 M/T/P/n/C₀/D₀/H₀ 等，避免正文与符号表记号冲突。
- **每给一个参数/公式都要可溯源**：成本参数、次品率来源、单位清楚。
- **决策结论用"0/1 决策表 + 指标值 + 依据"**：比纯文字更有说服力；多方案/多情形表要标"能否跨情形比较"。
- **代码/表/图做全做真**：随机种子、文件清单、运行说明；附录代码与正文一致、能复现。

## 建模决策链（结构层面）
- 先在"问题分析"里写明**范式切换触发条件**（如"2⁴=16 可枚举；16 决策/多工序则 DP；再大才启发式"），再进入建模，避免读者猜。

## 结果呈现（结构层面）
- 结论逐问给指标（元/件）与依据；用决策表+指标表支撑，而非大段文字；跨情形比较须说明口径。
