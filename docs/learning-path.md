# 数学建模能力学习路径（Learning Path）

> 目标：不仅会用这套工作流，更理解**每个门禁为什么存在**，从而把"机械正确性"交给 AI、把"建模判断力"练成自己的本事。
> 建议按站推进，每站完成"练习 + 自检"后再进入下一站。默认交互模式 `learning`（多提问、先答后建议）最适合本路径。

## 站 0 · 认识工作区（约 30 分钟）

- **做什么**：读 `AGENTS.md` 与 README，跑 `python scripts/validate_repo.py .` 与 `python scripts/run_tests.py`，理解目录结构。
- **背后的为什么**：
  - 门禁（G1–G6）存在的意义：把"不可信的过程"拆成"可核对的证据链"——每个数字、每个决策都有出处。
  - "AI 负责机械正确性、人类拥有建模判断"：竞赛要求真实能力，判断权交还给你。
- **练习**：给 `workspace/problem.txt` 放一道往年题（如 2024C），跑 `problem-parser`。
- **自检**：能说出 G2.5 是谁在做什么、`frozen_numbers.json` 为什么不能手改。

## 站 1 · 读懂题目（1–2 小时）

- **做什么**：`problem-parser` 产出 `planning/parse/problem_parse.json`；`problem-classifier` 分类任务型。
- **背后的为什么**：
  - 先解析后分类：不先弄清"要产出什么"，任何方法选择都是猜。
  - 解析必须区分"题目事实 / 数据观察 / 提议关系 / 需要你判断的假设"——这是建模的第一道分界线。
- **练习**：对同一道题，先自己写一页"目标-对象-约束-输出"清单，再与 parser 输出对照。
- **自检**：每个子问题 Qx 是否都对应一个明确输出？有没有你在替题目补充假设？

## 站 2 · 数据（1 小时）

- **做什么**：`data-auditor-cleaner` 产出 `workspace/data/data_profile.json` 与清洗数据。
- **背后的为什么**：原始数据只读——清洗是可复现的过程，不是一次性破坏；数据画像（缺失/不平衡/集中度）决定后面方法能不能成立。
- **练习**：对附件做一次"自己能解释每个清洗动作"的清理，再与技能输出对比。
- **自检**：每个被删除/插补的样本都有理由吗？数据画像能回答"方法 X 的数据前提满足吗"？

## 站 3 · 选方法（2–3 小时，核心站）

- **做什么**：`method-selector` 组候选并跑风险探针；你通过"选择卡"在 G2.5 拍板。
- **背后的为什么**：
  - 角色化候选（主方法 + 可用基线 + ≤1 条件备选）防止"堆方法凑数"——**少而精**才是竞赛气质。
  - 风险探针检查可执行性/数据覆盖/假设/输出退化/扰动/规模：选方法前先看"它在你数据上会不会瘫"。
  - G2.5 必须你决定：AI 可以给证据，但"为什么选它"是你的判断，论文里也要写得出。
- **练习**：对一个子问题，用 `method-index.md` 缩小候选；对每个候选写"为什么适合 / 为什么不选"各一句。
- **自检**：你能口头解释 baseline 为什么"可完成真任务"？备选的触发条件具体到可观察吗？

## 站 4 · 代码与实验（2–3 小时）

- **做什么**：`python/matlab-model-code-generator` 生成并运行，`python-code-reviewer` 五项检查，统一运行器产出快照。
- **背后的为什么**：
  - 只实现"批准的主方法 + 基线"：控制范围，避免实验失控。
  - 统一运行器记录预算/哈希/命令/环境：**能复现的实验才有说服力**；预算缩水必须降级声明（DEGRADED_SUCCESS）。
  - 五项评审（语法/输入契约/方法对齐/可复现性/输出契约）：代码要与方法卡一致，不是"能跑就行"。
- **练习**：故意改坏一个假设（如忽略缺失值），跑通"评审如何发现它"。
- **自检**：run_summary 是否完整？主方法与基线输出是否可比？随机种子记录了吗？

## 站 5 · 结果与论文（2–3 小时）

- **做什么**：`result-report-generator` → 你判结果（G4）→ `solution-package-builder` 冻结数字 → `paper-section-writer` 写论文 → G6 三审。
- **背后的为什么**：
  - 数字冻结（`frozen_numbers.json`）：论文里每个数都能溯源，改数走"解冻→改源→重跑→重冻结"，防止"改个数字凑结论"。
  - 论文以 solution package 为唯一素材：防止从散落实验里"脑补"叙述。
  - G6 三审（一致性/完整性/质检）是提交前的最后防线；`ai_trace_checker` 帮你守住"不像 AI 写的"这条底线。
- **练习**：用 `paper-polisher` + `ai_trace_checker` 打磨一段自己的结果分析；用 `latex_assembly.py` 装配出主文档。
- **自检**：摘要是否"每问必有一数"？每个数字是否来自冻结宏？物理解释是否你本人确认过？

## 站 6 · 审稿视角（1 小时）

- **做什么**：用 `quality-assurance-auditor` 的五维清单 + `consistency-auditor`/`completeness-auditor` 审自己的论文；最后跑 `docs/post-contest-review.md` 复盘。
- **背后的为什么**：能"审"才算真正理解——评审视角是最高层的学习。
- **练习**：把论文交给另一个不熟悉题目的人读 10 分钟，收集"哪里看不懂"。
- **自检**：你能指出论文中最强与最弱的各一个声明，并说出为什么吗？
