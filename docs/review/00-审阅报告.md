## 5. 六道门禁 G1–G6（＋G2.5）语义

门禁引擎 `python scripts/workflow_guard.py . derive Qx [--profile lean|submission|auto]` 从磁盘 canonical 证据推导，单调推进，manifest 只是缓存。

| 门禁 | 做什么 | 谁放行 | 过门核心证据（摘要） |
|---|---|---|---|
| G1 问题框架化 | 解析/分类/数据清点/成功标准/人工框架 | 你先确认关键框架 | parse(子问题须含 goal+非空 required_outputs)、classification(primary_type)、data_profile、framing 决策（parse 声明 human_decisions_needed 时必需） |
| G2 方法筛选 | 方法卡＋风险探针（可执行性/数据覆盖/假设/输出退化/扰动/规模） | AI 先干，证据说话 | `qx_method_card.md`（主候选+可用基线+可选条件备选及其触发）、`probes/risk_probe_summary.json`（main/baseline PASS 或合理 CONDITIONAL） |
| G2.5 人类选型 | 只有你拍板方法才允许生成代码 | **你** | 账本含 `DECIDED` `method_choice`（引用探针证据＋user source 原话） |
| G3 代码与实验评审 | 代码能跑、契约符合、可复现 | AI 自检＋机器校验 | 主/基线已运行；最新轮 `run_summary.json` 完整；语言评审五项 named checks PASS（G3 只卡最新轮，早期探索轮 advisory） |
| G4 结果判定与冻结 | 判结果/稳定性/声明范围；submission 期冻结 | **你** | lean：result/stability/claim-scope 三判定引证据（G4 结果判定子门）；submission 再加：最终方法说明/结果分析/稳健性报告/package_signoff/交付包/现行 `frozen_numbers.json` |
| G5 论文章节就绪 | 只用冻结数字写作，图过渲染校验 | AI 起草，你确认物理解释 | 三条 writer 前置（见下）＋人类确认解释/声明范围＋图 render 证据 |
| G6 最终审计 | 一致性/完整性/QA 三审 | 机器出报告，你终审 | 三个 audit 工件齐（内容由人在 handoff 判）；仅 submission 评估 |

writer 三条前置（AGENTS.md 单一定义，paper-section-writer 与 orchestrator G5 引用同一清单）：① `methods/Qx/qx_final_method_explanation.md`；② `results/Qx/reports/qx_final_result_analysis.md`；③ `results/Qx/reports/qx_solution_package_for_writer.md` 且章节每个数值 claim 源自现行 `frozen_numbers.json`。

铁律：改数=解冻→改 canonical source→重跑→重冻结＋`freeze_change_log.md` 记录；图分四型（Type1 不进论文，Type2–4 可进且 submission 下须 render 校验）；G5/G6 仅 submission 启用。

## 7. 人类决策规范（账本与选择卡）

- 每子问题一个**追加式账本** `methods/Qx/qx_decisions.jsonl`；全局框架决策放 `planning/framing_decisions.jsonl`。
- `DECIDED` 必须含嵌套 `source`：`source_type=user_answer`、`user_message_id`（DSH 下 `dsh:<$env:DSH_SESSION_ID>:<seq>`；无稳定 id 用 `unavailable:<platform>`）、`user_verbatim_answer`——没有可验证用户原话即无效（`validate_decisions.py`）。
- AI 只呈现证据与选项，**不得代写**理由/置信度/物理解释/提交授权；可逐字结构化用户原话，不得强化/编造。
- 判定谱系：机械事（AI 自查，勿问人）/半判定（AI 起草选项与缓解措辞，人接受/拒绝）/完全人判（方法选择、结果/稳定性/声明范围、物理解释、贡献、提交授权）。
- 选择卡出现点：通常每题两次（筛选前：输出形态/优先级/不可接受失败/实验预算；首轮实验后：继续/调整/回退），可加第三次（冻结前声明范围与置信度）；speed 模式可用矩阵卡一次同问多题，每题独立落账。
- 其它机器强制的人类决定类型：`package_signoff`（G4 冻结前）、`submission_authorization`（latex_assembly 消费，AI 使用声明）。
- 禁止为新手工作流创建 `*_modeler_decision.md`（旧文件迁移期可读）。

## 8. 运行模式与配置

`planning/session_config.json`：

```json
{ "schema_version": 1, "interaction_mode": "learning", "rigor_profile": "lean",
  "artifact_policy": { "require_lineage": true, "require_run_snapshot": true,
    "require_human_decision_source": true, "allow_downstream_on_blocked_gate": false } }
```

- `interaction_mode`: learning（多提问、先答后建议）/ speed（少提问、可并行建议）；兼容读取旧 `mode`。
- `rigor_profile`: lean（探索期：只留 manifest/method card/决策账本/探针/run_summary，G4 为结果判定子门）→ submission（交稿期：+最终说明/评审/分析/稳健性报告/交付包/冻结/论文/G5/G6 三审；qa_report/validate_manifest 按各自 rigor_profile 推导避免误报 GATE_BLOCKED）。
- `artifact_policy` 四开关全部默认 ON；关闭 = 全工作区放宽，须在 run snapshot 或 work log 记录理由，submission 前恢复默认。
- 可选 `deadline`（ISO-8601）→ derive 输出 advisory `deadline_hint`（四档文案：如"切 submission"、"停止新实验"），永不成为门禁输入。
- 变更影响分级路由校验：NONE（无校验）/ LOCAL（局部测试评审）/ CANONICAL（scoped consistency）/ FROZEN（thaw→改源→重跑→重冻结→scoped consistency）；不以"多文件变更"触发全量审计，但 submission 最终装配前必须跑一次完整三审计。

## 10. 训练模式与资源库

- 资源库：6 类目 `papers/ideas/figures/formulas/tables/assets`；条目自包含目录 `<category>/<entry_id>/{README.md, content/, code/, data/}`（README 即条目，content/code/data/figures 由 `resource_index.py` 归 supporting）；`index.json` v2 机器生成勿手改；`--check` 已纳入 validate_repo/CI；`figures/example-rank-bar/` 为真实示范（code 脚本相对自身路径写 content/PNG）。
- 训练闭环每轮 `results/training/roundN/`：A 闭卷 `training-solver`（禁读资源库、按门禁流程产出 solution/）→ B 开卷 `training-reflector`（按目标素养对照，写 reflection.md，自写不抄）→ C `training-auditor`（机械检查链 model_quality_gate/claim_coverage/abstract_checker/ai_trace_checker/leakage_check/figure_consistency_check/section_structure_check ＋ 六维评分卡 scorecard.json：agent 初评→你终评 1-5→范例对照评语；summary.json 雷达/排名聚合）→ 人类挑"逼近方向"→ 更新 `training_config.json`（mode closed/rounds/target_skills/problem_source/closed_phase_forbidden_paths/resource_categories）→ 下一轮。
- 六维素养：mathematical/innovation/figure/expression/evidence/completeness（各自机械锚点表见 docs/training.md）。
- 隔离：训练产物全在 results/training，竞赛流程不读资源库与训练结果；变体轮换题或 clean 轮禁读上一轮 solution；closed 无跨平台读钩子→双声明＋人工监督；冷启动"以己为师"（workspace/archived 归档→首批素材→沉淀 best 片段→库随使用增长）；版权告诫（assets/problems 只放有权使用的赛题）。

## 11. 工作记录树、赛后复盘与学习

- `records/`（advisory 叙事层，不参与门禁）：sessions（`YYYY-MM-DD-SSS.md` 当天追加）、subjects（Q1.md）、gates（时间线，命令拒绝回退与缺失证据）、decisions（从账本镜像，找不到账本拒绝生成，逐字引用）、retros（复盘骨架）。`work_record.py` 8 子命令；`--runtime` 自动探测 codex|claude|dsh；replay 从 manifests/账本/run_summary/frozen_numbers 自动生成当日草稿（replay:true 标记防误追加）。

## 15. 审阅观察与建议（非阻塞）

1. **CHANGELOG 测试计数口径**：0.9.1 内"Docs counts synced to executed total (271…)"与"Tests grew 247 → 269"并存，实测 271（含 1 skip）；建议统一口径（P2 类小问题）。
2. **hooks 平台边界**：SessionStart 横幅＋PreToolUse 守卫为 Claude 原生语义；DSH/Codex 默认 inert——文档已在 AGENTS.md/DSH 适配页显式声明并有可选补丁，但用户在不读文档时可能误以为全平台防护；guard 为 advisory（可被 Bash 绕过），权威在 validators——设计有意分层，建议保持措辞。
3. **模板接缝**：`templates/paper/main.tex` 是占位符骨架，不经 `latex_assembly.py` 装配直接编译只得空壳；README/教程宜点明（assets 审阅观察 ⑤）。
4. **技能内措辞不一致（minor）**：matlab vs python 代码生成器对 run-snapshot 机制措辞不同；python-code-reviewer 与 consistency-auditor 正文引用 validator 时部分无 `scripts/` 前缀（skills digest 注记）；实际执行仍以 scripts/ 下脚本为准。
5. **门禁归属推断**：多数 SKILL.md 不内嵌门禁代号/lean-submission 分支（只引用 AGENTS.md），图与文档标注"推断"关系即可，避免读作独立承诺。
6. **版本与署名**：两 manifest author（Chickeryxn）vs interface.developerName（Zhijun Zhang，LICENSE 版权人）为同一人的平台化署名；三处 version 0.9.1 一致性好。
7. 建议：若追求绝对隔离可把每次竞赛放独立目录/git worktree；`.gitignore` 已拦截竞赛内容，但 `git add -f` 仍可绕过（文档已声明）。
