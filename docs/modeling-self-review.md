# 建模自评清单（Modeling Self-Review）

> 用途：在 G2（方法筛选）与 G4（结果判定）之间对**建模方案本身**做一次结构化自评，补足"风险探针只查能不能跑、不查建模是否得当"的盲区。
> 适用：每个子问题 Qx 各填一次；由你（人类建模者）判定，AI 提供证据但不代写结论。自评结论写入 `methods/Qx/qx_method_card.md` 的"Compact history"或决策账本（`decision_type: assumption_necessity` / `claim_scope`）。

## 一、假设质量（对 `planning/model_assumptions.md`）

| 检查 | 判定 | 证据 |
|---|---|---|
| 每个假设都有"建模需要"（不是套话） | 是/否 | 假设行号 |
| 必要假设 vs 简化假设已分级 | 是/否 | 分级记录 |
| 最承重的一条假设，风险探针里查过吗 | 是/否 | 探针条目 |
| 若该假设失效，方案还成立吗 | 是/否 | 退化路径 |

## 二、复杂度合理性（防止"为了看起来高级而复杂"）

| 检查 | 判定 | 证据 |
|---|---|---|
| 方法复杂度有**明确收益**（精度/稳健性/可解释性），且收益可量化 | 是/否 | 对比证据表 |
| 主方法相对 baseline 的复杂度增幅，在竞赛时间预算内可完成 | 是/否 | 实现成本 |
| 换一个更简单的同类方法，结果是否实质变差（已探针） | 是/否 | 探针对比 |
| 没有为凑"模型数量"引入冗余模型 | 是/否 | 候选列表 |

## 三、可解释性与答辩性

| 检查 | 判定 | 证据 |
|---|---|---|
| 你（或队友）能用一句话向评委解释主方法 | 是/否 | 一句话版本 |
| 论文的"为什么选它"可落到方法与数据证据（不是感觉） | 是/否 | 方法卡 Rationale chain |
| 参数/权重有物理或业务含义可讲 | 是/否 | 参数表 |

## 四、公平性与防同质化

| 检查 | 判定 | 证据 |
|---|---|---|
| baseline 能完成真任务、输出可比 | 是/否 | 基线有效性 |
| 主方法与 baseline 在**数学机制**上确实不同 | 是/否 | 机制差异 |
| 备选（若有）的触发条件具体到可观察 | 是/否 | 触发定义 |

## 五、结果质量底线（配合 `scripts/model_quality_gate.py`）

| 检查 | 判定 | 证据 |
|---|---|---|
| 结果带不确定性（CI/误差）或显式声明不适用 | 是/否 | run_summary |
| 主方法 vs baseline 差距是"量化数字"而非形容词 | 是/否 | 指标对比 |
| 输出格式与 `model_contract.json` 的 `output_contract` 一致 | 是/否 | 契约对照 |
| 每个子问题都有至少一个可答辩的数字结论 | 是/否 | `claim_coverage.py` |
